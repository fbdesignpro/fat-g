# Chat protocol research

Purpose: answer the protocol questions in `docs/planning/_archive/chat/inventory.md`, ahead of chat planning. Findings and limitations: chat-protocols.md (private research note).

This is a research harness, not application code. It reuses M10's executable resolution, deadlines, launch ledger and process-tree cleanup. It never imports the Agent SDK at runtime. Do not run simultaneous spike invocations: the shared launch ledger guards cleanup.

## Commands

```powershell
node spikes/chat/inspect.mjs
node spikes/chat/trace.mjs --cli codex --scenario stream
node spikes/chat/trace.mjs --cli codex --scenario stream --confirm-turns 1
node spikes/chat/summarize.mjs
```

`inspect` runs CLI version/help and generates Codex plain/experimental schemas, with no model input. `trace` prints its scenario and does not launch a CLI unless `--confirm-turns` exactly matches the scenario input budget. It creates its own tiny text/image fixtures under the OS temp directory. `summarize` reads captured output and publishes only allowlisted facts in `evidence.json`; do not publish raw frames.

Scenario budgets: stream, followup, fork, question, async, interrupt and question-cancel: one input each; steer and async-answer: two; inspect and cleanup: zero. Total cap: **18 submitted inputs**, counted before submission. This is not a bound on internal model calls/tokens. A completed scenario requires `--again` to repeat, and still consumes the global budget. Start a separate deliberately budgeted investigation to extend coverage; do not reset the ledger to evade the cap.

Run stream → followup → fork in order for each provider; references are stored only in ignored output. `inspect` resumes the saved session without a prompt. `async-answer` is Codex-only; `question-cancel` is Claude-only. Cleanup uses only the saved list of this harness's Codex threads, in reverse creation order so forks precede parents. Native Claude sessions are left in CLI history; no direct transcript-file deletion.

All raw output, schema snapshots, ledgers and references are in ignored `spikes/output/chat/`. Scratch files are generated by this harness; no project data is needed. The Codex CLI may load its own user configuration/MCP startup; prompts explicitly forbid MCP/external tool use. Claude runs with empty setting sources, strict MCP and restricted tools. Aside from question fixture answers, the only allow rule is an exact harmless wait command; all other approvals are denied. One observed Claude wait command included extra output and was therefore denied, a limitation recorded in the report.

## Recorded pass

Codex 0.159.2 and Claude 2.1.268 on Windows x64; 18 submitted inputs, all process cleanup confirmed. `evidence.json` records scenarios, outcomes, event facts, timing and cache usage, and hashes the ignored raw captures and selected schemas. The Claude SDK declarations read during interpretation were 0.3.278 and are newer than the installed CLI.

The first Codex cleanup attempt refused the parent while a fork referenced its history; a zero-input retry after deleting the child removed the parent. This is protocol evidence, not a process leak. Claude's named fixture sessions remain available through its own UI.

The evidence summary is not a replay fixture and should not be used to claim production conformance. Feature implementation must add focused replay/race tests for its final adapter contract. Live probes intentionally did not grant file modifications, run actual MCP elicitations, generate paid images or force compaction.
