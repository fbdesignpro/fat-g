# 0016 — A model preset is what every session start takes

> **Rule:** a model preset is a provider, one of its instances, a model — by the exact version it names, never an alias its CLI may move — an effort and a speed tier (null for standard speed). A named selection is saved in preferences and edited in Settings → Presets; availability never changes it. Every session start takes the five selection fields, and the session's record keeps those alone. A provisional draft may change its selection before starting or entering a plan workflow; afterwards the model and account are fixed and only effort and speed tier can change, and a session whose version its account no longer lists takes no prompt: no other version is put in its place. A session type (new spec sheet, new plan) defines a session's first turn only, and is never stored.

- **Status:** Accepted by the maintainer, from M14 (C78, C80, C83–C85, C89, C94, C95). Implemented in M14, with presets that are unnamed and unsaved. Amended by M14b (S10, C25, C27, C55–C57, C63; [0017](0017-provider-instances.md)): the preset's instance, and the model fixed at create. Amended: the speed tier, a fifth field. Amended: the model as its exact version.
- **Applies to:** the session record, `sessions:create`, `sessions:setDraftPreset`, `sessions:setSpeed`, the send gate, the new-chat screen and model picker, the effort menu, and Settings → Presets.

## Context

- A session runs with a model and an effort level of one provider. Choosing all three at once, each time, is what starting a session asks of the user.
- The CLIs layer their own defaults: what a session gets depends on the user's configuration, not only on what the model list marks as default (models research §4 (private)). A session that is to be resumed, and shown, with the model it was started with has to record what was asked for.
- The maintainer wants the same combinations reused wherever a session is started, and later given names of their own.
- Kinds of session — a new spec sheet, a new plan, a review — differ in what the first turn says, not in what the session is.

## Decision

1. **A model preset** is a provider id, an instance id, a model key and an effort id; the effort is null for a model with no levels. A saved preset adds a name and is keyed by a stable UUID in preferences. *(M14b, C25:)* the instance is one of the provider's accounts ([0017](0017-provider-instances.md)). the fifth field is the speed tier: the id of one the model lists (`CatalogModel.speedTiers` — Claude's `fast`, a Codex service tier such as `priority`), or null for standard speed, which is every default.
2. **Every session start takes one.** `sessions:create` takes a project and a preset, and main refuses a preset whose provider the project does not offer or is switched off, whose model the catalog hides or does not list, or whose level the model lacks. *(M14b, C25, C30:)* it also refuses one whose instance is not configured, is switched off or cannot run. The model and the level are checked against that instance's own list, and a project stays offered to providers: every switched-on instance of an offered provider can be chosen for it. so is the speed tier: one the model does not list is refused as `speed-not-listed`, and any tier asked of an instance whose catalog entry says fat-g cannot ask for one (`speedTierRequest.possible`, [0013](0013-catalog-format-and-layers.md)) as `speed-unavailable`. Standard speed is never refused.
3. **The record keeps the five fields**, the model, the effort and the speed tier as the catalog's key, effort id and tier id ([0011](0011-records-store.md), item 4). It keeps no preset id and no preset name: a preset describes a start. **Provisional changes:** main-only `sessions:setDraftPreset` validates the project, account, model and effort and serializes the change against first-send admission. It refuses a started session, conversation content beyond its draft, or a plan workflow. It updates the same record and runtime presentation, retaining the draft's text, images and Plan intent. A valid same-provider permission choice stays; changing provider resolves that provider's defaults. Unsupported selected skills remain selected and block Send with an explanation. Once started, the provider, account and model key are fixed, preserving provider caches; only effort and speed tier can change. **The speed tier after the start:** `sessions:setSpeed { id, speed }` mirrors `sessions:setEffort` — the same holds, then the tier checked against the session's own instance as a preset's is — and the change applies from the next turn. Each turn sends the recorded key, effort and tier ([0018](0018-codex-sessions.md), [0020](0020-claude-chat-sessions.md)), and a model the session reports is shown, never stored.
4. **One set of helpers** resolves a preset for main and for the page (`src/shared/contracts/presets.ts`): which models are offered as tiles, which tile a key selects, which level a model takes, the default preset, and the preselection.
   - The **default preset** takes what the provider lists: the first offered provider's listed default model at that model's listed default effort; without a listed default model, the first model; without a listed default effort, the middle of the model's levels without the caution flag, the upper of two middles (the highest, until then, made Claude's Max every default, where the CLI's own is High); for a model with only caution levels, its first level. A change of model or account that the level in force does not survive takes the same rule.
   - The **preselection** is the preset of the project's newest session, else of the newest session in any project, else the default, skipping one a start would refuse. Nothing is saved for it. *(M14b, C27:)* it carries the instance of the session it comes from, and the default names the first offered provider's first switched-on instance that lists a model. it carries that session's speed tier too, where the tier can still be asked; else the same session's preset at standard speed.
   - **The speed tier** is kept through a change of model or account that lists it, as a level is, else it falls to standard speed (`speedFor`); nothing chooses a tier for the user.
5. **In M14 presets are unnamed and unsaved.** The New session popup builds one from a model tile and an effort level, and that is all.
   **Named presets (name limit amended).** Preferences revision 11 adds the saved list and Settings → Presets adds New preset, Edit and Delete. Names use the shared cleaning rule, limited to 18 grapheme clusters; existing longer names are shortened with an ellipsis within that limit when read. Both naming fields cap typing and pastes at 18 visible characters without splitting Unicode clusters. The larger new-chat capsules show their names at 16 px. An unavailable combination stays saved and can still be renamed, changed or deleted; the page reports its live reason without substituting another account, model or effort. Only the chosen keys, ids and name are saved, never a model list or an account's identity. The new-chat screen offers the list; review and review-integration remain later work.
   **Save from the picker.** Save as preset keeps its row under Apply at all times, disabled unless a selection matches no saved preset by all five fields and preferences can be saved. A modal names that fixed selection in a standard 224 × 62 px preset capsule, with the name field in its title, a thin focus outline and a small gap above the descriptive line. Save and apply writes the preset through preferences, then applies it to the draft; only a successful application touches that preset's recency. A refused save retains the name and can be retried; a refused application returns to the chooser with the preset saved. Cancel or Escape returns to the unchanged chooser without saving. Settings lists the same standard-size preset capsules with Edit and Delete immediately beside them; account identity remains in the capsule's tooltip, and unavailable entries stay visible and editable.
   **Initial new-chat screen.** A project's `+` creates one provisional session with the existing preselection, without starting an agent turn, and displays the composer directly over the grid. The visit is transient renderer state; navigating away ends it. Afterwards the screen follows the draft rather than the visit: a selected session no turn of which has run is shown on it, with its saved prompt, so a draft left with a prompt begun returns to the same screen (amended, replacing the normal chat for a revisited draft). An accepted Send, taking part in a plan, or an image or plan tab of the draft open shows it as the normal chat instead. Settings and the model picker do not end it. Repeated `+` focuses the existing input while the draft is empty; once text or images have been entered, it saves that draft and opens a fresh one, in the same project or another. Selecting another session also saves the departing draft. A saved unsent draft stays in the list and reopens with its composer intact. Before its first accepted Send, Cancel stands beside Send, its capsule has a cancellation cross in place of the usual action menu button, and its right-click menu offers the same cancellation. Cancellation removes the draft without a confirmation; main refuses it if a first turn or plan workflow has already started. Picker Apply changes the same draft; Escape and outside click discard pending choices. Done and shelving retain their existing screens.
   **Preset ordering.** Revision 12 keeps a global `presetRecency` list of preset IDs, newest use first, merged by main's single-ID `usePreset` preference operation. Only successfully applying a capsule touches its exact ID; manually choosing a model does not. Never-used entries retain saved-list order, and deleting an entry removes its recency. Each carousel visit keeps the recency order it opened with and retains its page when a preset is chosen; usage is saved immediately, and opening another new chat or navigating away and returning adopts the updated order. Preset edits, additions, removals and availability still update during the visit. Up to three capsules per row and two rows form one horizontal page; capsules are at most 260px wide, and narrow layouts reduce columns. Unavailable presets remain visible and unselectable with their current reason, including project restrictions.
   **Recents.** Revision 13 keeps `recentModels`, the last twelve distinct provider, account instance, model key and effort combinations, newest first across all projects. Main records a combination when a provider-bound prompt is accepted: an ordinary or plan/review prompt, a dispatched queued message, Send now, or an aside. A steer uses the running turn's effort, not a choice for the next turn. Draft changes, capsule clicks, queue writes alone, refused sends, locally handled commands, secretary calls and sub-agent activity do not count. A history failure never changes an accepted send's result. No content, project or session id, label or timestamp accompanies a combination, and removal of a session does not remove it. There is no historical backfill. Below Presets when present, Recent settings shows the newest available combinations in one row of up to three capsules, reducing to two or one at narrow widths, with no arrows. Availability, including project restrictions, is checked before taking those entries; an empty section reserves no space. A recent changes the same draft and returns focus to its input. Both sections share their capsule presentation, and the lower separator follows their actual height in document flow. Recents excludes combinations matching any saved preset, before taking the visible entries; its heading is "Recent settings". Matching uses all five selection fields, including the account and speed tier; history is retained, so removing or changing a preset makes its recent combination eligible again. This applies wherever the shared Recents section appears.
   **The speed tier in presets and recents.** Revision 16 adds the tier to a saved preset and to each recent combination; an entry without one is no longer read. Main records the tier in force with the effort, and a Fast and a standard choice are two combinations, in Recents and in a capsule's match (`modelSelectionKey`). The secretary, which counts for nothing here, always runs at standard speed.
   **Presentation.** The list and editor show the model's current avatar from the catalog, using the shared avatar component's fallback. Account labels follow the provider's name in parentheses only when that provider has multiple configured accounts; a single account adds no label. Only an unavailable combination shows a status: “Unavailable” in red on the model's line, its reason in the tooltip and accessible label. These are live presentation details, never copied into the saved preset.
   **The model chooser in capsules.** One chooser (`src/renderer/src/model-chooser/`) holds a selection for whatever applies it: the providers' accounts, each model as a capsule of the Recents and Presets look — its 60 px avatar with its overlay, its name on one line, and the CLI's own description of it wrapped to two lines, the most the avatar's height holds, whole in the tooltip and the accessible description — and the chosen model's levels on the right. The chosen capsule alone carries the chosen level's marks. Each provider starts with one column of up to eight capsules, fewer where the available height requires it; Show more at its foot reveals one more column for that provider. A saved selection beyond the first column is revealed on opening, and expansion does not change the selection. The capsules are 224 px wide, with the chooser's descriptions at 11 px; Recent settings uses the same width and keeps its existing 12 px detail text. Columns narrow only when the revealed columns need it. The new-chat screen's picker is the chooser in a popup with Apply. Its Apply and the model dialog's confirmation and Cancel buttons stand directly above the effort selector in its column.
   **The speed tier, shown (the maintainer).** It is chosen and said with the effort, never around the model's name: the chooser lists a model's tiers under its levels — one tier a check, "⚡ Fast", several a choice with Standard first — and a chat's effort menu lists them under its levels the same way, a change applying from the next turn as a level's does. The effort bar, the new-chat model button and every capsule say the level, then the tier by its short name: "Extra High - ⚡Fast", "⚡Ultra" for a tier named "Ultra fast"; standard speed adds nothing. What a tier costs is said on hover and under it once chosen, as a level's warning is; an account fat-g cannot ask for a tier keeps the control, disabled, saying why. A fast session's avatar carries the bolt of [0032](0032-avatar-overlay.md). Settings → Presets chooses it with a Speed list. Where a chat's last turn asked for a tier and its CLI says it ran at standard speed, the effort bar says **"Not fast"** in red in place of its text — the level and "Not fast" together do not fit the column — its hover note giving the level, and it and the menu's saying what was asked and why it was not served (no extra usage left, fast mode paused, a tier the model does not offer); a turn served fast takes it back. It is a live reading of the summary, never stored.
   **Presets in reviews (presentation amended).** Review by model and an integration into a new session choose their preset in one shared model dialog. It opens with three columns — Presets, Recent settings, and Custom — in a frame sized to those columns, wrapping in a narrow window. Capsules match the regular chooser's 224 × 62 px size; Custom holds one matching button, "Custom model & effort". Presets and Recents start with six entries each, with Show more revealing the next six in that column. Presets retain their visit's order and unavailable entries; Recents filters availability and saved-preset matches before taking its entries. Empty columns say so. A capsule selects its combination and starts nothing; the current selection and the dialog's action remain visible below the lists. Custom opens the regular model/account, effort and speed chooser with Start review, or the integration action, and Cancel above Effort. Custom's Cancel or Escape discards its choices and returns to the columns with their selection, expansion and order retained; their Cancel or Escape closes the dialog. Only successful confirmation touches a clicked preset's recency, when the final selection still matches it. Main checks the chosen preset as `sessions:create` does, through one admission function, before anything is made.
   **Clear recent model list.** Settings → Diagnostics clears `recentModels` through the preferences store, without changing saved presets or their order. The list fills again as prompts are accepted.
6. **A session type defines the first turn, not the session.** It is chosen where a session is started, shapes what that turn sends, and is not stored in the record. M14 has one type, the regular session, and no control for it.

## Consequences

- M15 and M16 start a provider session with the record's model and effort, never with the CLI's own default; with its speed tier too, standard speed asked for explicitly where a CLI would otherwise take the user's own configuration.
- The saved list, editor and new-chat carousel exist, and the review and integration dialogs offer them. Session records contain no saved-preset identity.
- The initial screen's avatar, name and effort are one model-picker button. With no available models, it hides the selector and offers an inline Preferences link to Accounts; an existing draft stays editable while Send is unavailable. Ordinary sessions retain the fixed model display and effort menu.
- The initial input has the normal chat's maximum width, wide-window spacing stays fixed, and the project's `+` has no persistent active highlight.
- Preset capsules matching the current provider, account, model and effort have a persistent thick outline in the text's colour — black in the light theme, white in the dark (where black did not show) — including after manual picker changes; the chooser's chosen model capsule has the same. Matching duplicates are all marked; the outline does not imply a saved-preset identity in the session. Hover and keyboard focus keep a separate yellow outline outside it.
- Only the composer is width-capped: both separators span the new-chat display between matching left and right insets. The heading's first line aligns its visible ink with the sessions list's top edge: cap-height trimming plus a measured inset for that line's actual letters preserves accents without leaving the font's unused ascent above ordinary titles. One physical pixel protects the rasterized edge. The initial input has a white background as a visual trial, with dark text and controls in either theme.
- The heading reserves a fixed slot based on the full-size 90px project title (scaled at narrow widths), keeping the top separator at the same height for either arrangement. When they fit, the project and half-size `// new chat` share one full-size line and baseline. Otherwise the suffix moves to a second line at 65% of the project title's size, and both shrink proportionally until their rendered width and combined height fit the same slot. Resizing or renaming recalculates the fit and restores the full-size inline arrangement when space permits.
- The most recently used preset IDs are preferences; the initial-screen flag and carousel page are not persisted. Preselection continues to use usable session history.

## Amendment: speed on reply bars

Each dispatched turn snapshots its requested speed tier (id and name), or null for standard speed, in the conversation store alone (0019, format 13). The assistant's interlocutor bar adds only one lightning bolt for Fast, or three adjacent bolts for Ultra fast, beside its model name. No speed words appear in the bar. Hover and accessible text describe the requested tier, without claiming that it was served. This is an exception to item 5's placement rule for the chooser, capsules and effort bar, which keep their existing presentation. Changing the session's speed affects later dispatched turns only. Side questions record their own requests; sub-agent bars never inherit the parent's tier. Imported history and local commands have no recorded speed and show no marker.

## Amendment: exact versions

- **The model is the exact version.** A preset's, a session record's and a recent combination's model is the catalog's key, and the key now names one version ([0013](0013-catalog-format-and-layers.md), as amended): Claude's `claude-fable-5-1[1m]`, never the `fable` its CLI points at a newer version when it updates. Until then a Claude key was the model list's alias, and an update of the CLI fat-g runs — from 2.1.302 to 2.1.321 — moved every chat, preset and recent keyed `fable` from Fable 5.1 to 5.2, in what each showed and in what each ran (models research §7 (private)). Nothing else changes in what is stored or sent: every turn's `--model` is the key, so a chat resumes on the version it was made with.
- **A version no longer listed takes no prompt.** A session whose model its account's list, once reported, does not name by its key — hidden models count — is refused by the send gate as `model-not-listed`, for a prompt, an aside's question and a change of mode alike, and says so in place of its input with no remedy. Its earlier messages are still read. No other version, nor the alias, is put in its place. Before the account's CLI has reported its list nothing is decided. A user whose CLI still runs the version can add it back in `catalog.json` ([catalog-override.md](../catalog-override.md)). Main refuses an unstarted draft whose model is gone the same way; the new-chat screen already said so.
- **No conversion (pre-release, [0014](0014-format-compatibility-starts-at-first-release.md)).** The stored formats do not change: the model is still a string. A record, preset or recent that holds an alias from before is no longer listed: the chat stays readable and takes no prompt, the preset shows as unavailable until it is chosen again, and the recent drops out. The maintainer chose this; a session's handoff to another is the planned way on for such a chat.
- **Not changed:** an unlisted model is named by its id (`genericModel`), its avatar's overlay reading its version from it; a sub-agent launched by an alias is named by it until its own frames name the version; for Claude, an avatar assigned by key and one assigned by version ([0031](0031-avatars.md)) now name the same thing.

## Revisit when

- Saved presets are offered at a session start; the session still records the five selection fields alone.
- A session type needs something a first turn cannot carry, such as a tool set or a sandbox of its own.
