# 0023 — A CLI's own commands pass through; fat-g intercepts piecemeal

> **Rule:** a CLI's own commands and skills reach it as the user wrote them. Before a prompt is sent, fat-g intercepts only the commands that would change what it tracks — the conversation in use, the session's model, its process, its login, since M22 the mode it runs under, and its speed tier — and answers each in its own words as the turn's message, with no model called. Every other command runs as it does in the terminal, and the composer lists them from what the CLI reports. The same approach, intercept the few and pass the rest, is the pattern for other CLI features reached from the chat.

- **Status:** Accepted by the maintainer, from the M20b outline's question on Claude's `/btw`. Takes effect with M20b, which lifts the flag and holds the intercept list, and M23, which lists the commands in the composer. Supersedes M16's C69 and amends [0020](0020-claude-chat-sessions.md), items 4 and 6. Implemented in M20b (C54–C60): the launch passes no flag, and the intercept list — a closed constant in [`chat-commands.ts`](../../src/main/providers/claude/chat-commands.ts) — is `/clear` and `/model`. M20b's K2 wrote the other candidates as prompts under the new launch: `/exit`, `/quit`, `/resume`, `/login`, `/logout` and `/btw` each got the CLI's own answer that it is not available in this environment, with no model called and nothing changed, so none is on the list; `/compact` compacted. M22, added the permission policy to what fat-g tracks and left the list as it was (C7; [0027](0027-execution-permissions.md)): no command of either CLI was shown to change it, which item 2 records.

  M23 (C58–C67): the composer's list is built — a `/` at a draft's start opens a menu of fat-g's own two first, then the CLI's commands, then its skills, read from main as it opens. A row chosen puts its name in the draft; a Codex skill chosen also goes as its own input, resolved before the send, and a command typed and not chosen is still text. The intercepted list is unchanged.

  [0016](0016-model-presets.md), item 2: Claude's `/fast` joins the list, since fat-g now asks for a session's speed tier with each turn ([0020](0020-claude-chat-sessions.md), item 2); the list is `/clear`, `/model` and `/fast`, and the menu's own rows three.
- **Applies to:** the Claude chat launch and the path a prompt takes before `chat-wire.ts` writes it (`src/main/providers/claude/`); the composer; Codex once its app-server is seen to take a command in a turn's text, which nothing has observed. Builds on [0004](0004-never-touch-credentials.md), [0016](0016-model-presets.md), [0019](0019-conversation-store.md) and [0020](0020-claude-chat-sessions.md).

## Context

- M16's spike K19 (Claude Code 2.1.268) wrote the CLI's commands as prompts without the flag. The CLI ran them: `/model haiku` changed the model with no model call, the next `init` naming it while fat-g's record named another; `/clear` reset the conversation and gave the process a new session id, so the record's reference no longer named the conversation in use; `/compact` and a skill's name ran. The maintainer then had a chat session launched with `--disable-slash-commands` (C69): every prompt became plain text, and a command's name got the CLI's own answer that it is not available.
- The cost showed with asides (M20b). The side question fat-g wants is the CLI's `/btw`, reached as a control request, and the flag may gate the request as it gates the command. The flag also takes `/compact`, the user's own commands and every skill away from the chat, which the terminal has.
- T3 Code, read on its `main` branch at the time, keeps the commands: its composer's `/` menu lists the CLI's commands from the `init` frame; a provider command must start the message to run; `/compact` passes through; a `$skill` mention is rewritten to the CLI's `/name` form; `/model` and `/plan` are its own commands, handled before anything is sent; and it passes `--disable-slash-commands` only to its title-generation launches, which need no capability. The maintainer adopted that approach, and named it as the pattern for other CLI features later.

## Decision

1. **The launch passes no `--disable-slash-commands`.** The CLI's commands and skills are on, as in the terminal; the tool list is unchanged, so the model is still offered no `Skill` tool and runs a skill only at the user's word.
2. **An intercept list, fat-g's own, per provider, closed and tested.** A prompt that the CLI would run as a command on the list — one that starts with the command's name, as the CLI reads one; a name later in the text is prose for both — is never sent. fat-g answers it as the turn's message, in its own words, as a notice of the conversation store: no model is called and no usage is spent. The candidates: `/clear`, which resets the conversation and its reference (0019; 0020, item 11); `/model`, since a session's model is fixed (0016); a command that ends the process or resumes another session; and a login or logout (0004). M20b's sheet settles the list after its spike writes each candidate as a prompt, and the list is reviewed with each CLI version the captures record. *(M20b, C35, C55, C56:)* settled as `/clear` and `/model`, then joined by `/fast`, which would turn Claude's fast mode on or off behind the speed tier the session records and asks for with each turn ([0016](0016-model-presets.md)): its notice says that fat-g asks for the speed itself, and to choose Fast with the effort. An intercepted command is a turn of the session's conversation whose end is fat-g's own: the prompt as the user's message, fat-g's notice as the turn's message — naming the command and the way in fat-g, and claiming nothing of what the command would have done — and no provider's end. *(M22, C7:)* what fat-g tracks now includes the permission policy a session runs under, its chat's mode ([0027](0027-execution-permissions.md)), and a command that changed it would join the list. None was shown to, so the list did not grow: written as a prompt, Claude's `/permissions` is answered by the CLI itself as not available, with no model called and nothing changed, and neither it nor `/add-dir` is among the commands the CLI reports; on Codex a prompt is the model's text, and no command of the CLI's was traced as one. What guards the tracked policy is the check and not the list: each provider's reports are held to the chat's mode, and a difference sends nothing more ([0027](0027-execution-permissions.md), item 10).
3. **Everything else passes as written.** `/compact`, a skill, the user's and a plugin's commands go to the CLI in the prompt's `user` frame as any text does, and the CLI's answer is the turn's message as any. fat-g shows what the CLI reports and claims nothing of what the command did: a `/compact` is not shown as a smaller context until the CLI says so.
4. **The composer lists them.** `/` lists the CLI's commands and skills as its `init` frame reports them, the intercepted ones shown as fat-g's own with their notice; a command must start the message to run, as in the terminal (M23).
5. **The pattern.** When a CLI feature reached from the chat would change what fat-g tracks, fat-g intercepts that case alone and passes the rest, rather than switching the feature off. A record names each list.

## What is left out

- Commands of fat-g's own, such as T3 Code's `/model` and `/plan`: later work, each with its own record.
- Codex's commands through its app-server: nothing has observed one being parsed from a turn's text; M23's spike asks.
- Rewriting a `$skill` mention into a command, as T3 Code does: a prompt goes to the CLI as the user wrote it.

## Consequences

- A command that passes through does in fat-g what it does in the terminal: `/compact` rewrites the context the model holds, a skill runs as the user wrote it. What fat-g tracks is kept by the intercept list, not by the launch, so a command missing from the list is a defect of the list.
- `PRIVACY.md`'s sentence that Claude's skills and slash commands are switched off changes when M20b lands, and so do M16's command tests (V27).
- A command the CLI does not know still gets the CLI's own answer, as a `<synthetic>` frame, as before.

## Revisit when

- The CLI offers a documented way to list, allow or disable single commands: prefer it to the intercept list.
- Codex's app-server parses a command from a turn's text: the Codex list is written.
- A command on the list becomes something fat-g wants to offer itself, a `/model` for a new session for instance: that is a command of fat-g's own, and a record of its own.
