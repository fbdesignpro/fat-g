# 0010 — Pet: the sessions running or waiting on the user, by name

> **Rule:** the Pet lists the sessions running or waiting on the user, by name under their projects' names, from main's own allowlisted view — never account identity, a prompt, a message, an action's label or an avatar's folder names; a press there opens the session in the Main window. Session summaries live in main, a capsule shows only what its summary holds, and "attention acknowledged" is a field main holds.

- **Status:** Accepted by the maintainer; Pet work was then deferred to the end. The three habits of item 5 are followed since M14 (S5, C15, C20, C34, C65). The Pet's list built at the maintainer's request: items 2, 4 and 6–9.
- **Applies to:** the Pet window, app-state projections, session contracts, the title strip's Pet button. Supersedes the Pet content planned in Phase 1 M8.

## Context

Phase 1 built the Pet window's shell: an opaque, frameless square, always on top, that receives app state with account identity removed. Its content (compact usage meters, M8) was deferred.

The layout overview (private) redefines the Pet as a list of the active session capsules "until they get clicked on (either in the main window or the pet itself)". A list has a variable height, and capsules show session names. The Pet is always on top, so what it shows appears in screen shares.

## Decision

0. **Naming** *(the maintainer)***:** the user sees the Pet as the **mini window** — the Settings switch ("Show the mini window"), the title strip's button and tooltip ("Mini window"), the × ("Hide the mini window"), its window title, `PRIVACY.md` and `README.md`. The code keeps "pet": its files (`pet-window.ts`, `PetApp.tsx`, `pet.html`, `src/shared/contracts/pet.ts`), its window kind and IPC channels (`pet`, `pet:*`), the app state's `pet` and `petSize`, the preference `windows.pet`, and these records. New user-facing text says "mini window"; nothing is renamed in code or in stored formats.

1. **No Pet work until chat is well along.** The Pet is a convenience. *(Done: built.)*
2. **Content** *(the maintainer)***:** every active session whose turn runs, or that waits on the user — a question, an approval, a plan or a review pending, or a Ready, Error or Stopped not yet seen — under a thin row with its project's name, in the Main window's order (visible projects, then hidden ones; starred first). A Ready seen in either window leaves the Pet; a pending decision stays until resolved. A chat waiting on a plan another chat holds is not listed for that wait. With none, one line says so.
3. **Names on the Pet are acceptable.** The maintainer sees no privacy concern in showing session and project names there. Account identity (email, organization) still never reaches the Pet.
4. **Shape:** a fixed width per size and a height that follows the list, set by main from one geometry the page lays its rows out by (`src/shared/contracts/pet.ts`). ** The nearer horizontal and vertical edges of its display's work area stay where the user left them: in the bottom-right corner it grows upward and toward the left; in the top-right corner it grows downward and toward the left. Those edges stay chosen through list changes until the user moves it again or the display layout changes. At the opposite work area edge the window stops and the list scrolls. Its size is whole device pixels on its screen — an even number of DIPs at 150% — or the page, laid out at whole DIPs, is cut by a pixel; main puts it back at that size at the end of each drag, at any change of size it did not make, and when a screen's scale changes, since a drag between screens of different scales leaves the size Windows scaled it to (`src/main/windows/pet-fit.ts`).
5. **Three habits keep the Pet cheap to add later:**
   - Session summaries live in main-process state, not in the Main window's own store.
   - A capsule gets everything it shows from the session summary. Preferences never reach the Pet, so main resolves the avatar reference and the theme.
   - "Attention acknowledged" is a session field held by main, so a click in either window acknowledges the same notification. Pending decisions — questions, approvals, plans and reviews — stay unacknowledged until resolved; visiting never dims them. Ready, Error and Stopped are still acknowledged by visiting. ** The selected session's READY is acknowledged as it arrives only while the Main window has the focus; one that arrives while the user is away stays lit, in the Pet and on the Main window's icon, until the window takes the focus — unless a press on the Pet brought it forward to open another session, which leaves it lit.
6. **M8's compact usage meters in the Pet are dropped.**
7. **Two sizes:** `capsule`, the Main window's capsule — its avatar at 60 px with the overlay, the name on two lines, the status bar under it — and `compact`, a smaller row: a 36 px avatar, the name on one line over the same status bar. A toggle on the Pet's bar switches them (`pet:setSize`); the choice is kept as `windows.pet.size` in the preferences, added at revision 16 at the maintainer's choice ([0005](0005-preferences-compatibility.md)).
8. **A press on a capsule** brings the Main window forward and has its page open the session as a press on its capsule there does (`pet:open`, then the `sessions:reveal` push): the departing chat's unsent text handed over, the session selected, which acknowledges it, and its prompt given the keyboard. `sessions:acknowledge` stays the Main window's and is called by no window. ** A press on the empty list's line brings Main forward, restoring it if minimized, without selecting a session (`pet:showMain`); the line is a keyboard-accessible button across the content area.
9. **What reaches the Pet:** its projection gains a view built by an allowlist (`src/main/state/pet-view.ts`): of each listed session its id, provider, name, the name's source, its creation time and its speed tier; of its summary the status, the turn's start and held time, the worker count, the attention's kind, count and acknowledgement, the plan's wait, the effort and the action's kind — never its label or detail, which can name a file or a command; its avatar's file ids and overlay ([0031](0031-avatars.md)), never its reference; and the colour, fallback mark, logo and stream of the listed sessions' providers, never a model list or the catalog. The provider's bundled logo reaches the Pet for avatar placeholders. *(M105)* The action also carries a closed waiting reason (`provider` or `subagents`) and an optional known target count (1–256). A transient visible-fallback hold carries only the previous kind, safe reason/count and its original deadline. These nested fields are copied by allowlist, without labels, details, target ids, names, paths or provider prose; none is stored. Reopening consumes the remaining deadline. Its avatar projection is unchanged. The Pet's window controls may ask main for `pet:hide`, `pet:setSize`, `pet:open` and `pet:showMain`.

10. **Automatic hiding** *(the maintainer)*: `windows.pet.autoHideOnMainFocus`, true by default, hides the enabled Pet while the Main window has focus and shows it without taking focus when Main loses focus, is hidden or minimized. Every show reapplies its native always-on-top level and raises it without activation, so returning from automatic hiding keeps it above Main and other applications. Settings > General places the checkbox indented beneath Show the mini window and disables it while that parent is off, retaining the choice. Changes apply at once, including while the Pet loads; hiding for focus never changes `windows.pet.visible`, and a Pet switched off stays hidden through focus changes. ** Switching the Pet on explicitly shows it even while Main has focus, through its first load if necessary; automatic hiding resumes the next time Main gains focus, or when the auto-hide option changes. This exception is in memory alone. Preferences revision 21 ([0005](0005-preferences-compatibility.md)).

## Consequences

- *(M14, amended for pending decisions):* the habits as built. Each session's summary is held by the session service in main (`src/main/sessions/`) and reaches the Main window inside the app state. A capsule draws only what its summary and its record view hold; its avatar comes from the catalog's presentation, which main resolves. "Acknowledged" is a flag of the summary, set for Ready, Error and Stopped by `sessions:select` and by `sessions:acknowledge`. Both channels leave pending questions, approvals, plans and reviews lit. These decisions use the attention colour pair in the capsule and local status bar until their existing resolution actions release them; withdrawal and termination still settle requests. This changes no rule about which events raise attention or which pending content survives a restart.
- *(M102, [0031](0031-avatars.md):)* the avatar a capsule draws is resolved by main into the session's entry and the catalog model's, beside its summary. The Pet's view carries a listed session's file ids and overlay; never the listing, a reference or a family's name, and the Pet may not ask for any of them.
- ** The Main window's title strip holds a Pet button after the gear: pressed while the Pet is wanted, changing `windows.pet.visible` as Settings' checkbox does. The Pet's × still hides it. ** The off icon is outlined and muted gray, retaining its full hover response; only a disabled control loses opacity.
- ** The Pet's capsule and the Main window's draw one status bar (`src/renderer/src/sessions/CapsuleStatus.tsx`), which flashes inverted, yellow on black, when it turns to an attention while drawn — six times a second for three seconds unless Settings → Appearance turns it off or sets another speed or duration, carried to the Pet in the app state's `appearance` ([0005](0005-preferences-compatibility.md)) — held still under reduced motion, and never for one it showed when first drawn or for PLAN READY raised by the user bringing an existing plan through Review. That user-initiated attention carries `flash: false` in the live summary, including the Pet's allowlisted view; it stays lit and unacknowledged. The Main window's icon and the Pet light on the same unseen attention (`unseenAttention`, `src/shared/contracts/sessions.ts`).
- The rest of M8 (privacy and provider documentation, tray, copy diagnostics) is placed by the roadmap (private).

## Revisit when

- Users ask to keep names off a window that is always on top. An option to hide names would cover it.
- The list proves too long or too short: idle sessions, or a cap on rows.
